# Аналітика через Claude Cowork

Цикл публікації статті в «Аналітиці» поділено на дві частини:

1. **Cowork — дослідження.** Скіл `cyberplain-analytics-brief` збирає першоджерела, звіряє факти, зіставляє з ATT&CK v20 і
   портфелем рішень і віддає **MD-бриф** у точному форматі.
2. **Claude Code — публікація.** Скіл `.claude/skills/publish-analytics` перетворює бриф на JSON, англійський оверлей і
   SVG-схему, збирає сайт, перевіряє сторінки й комітить.

```
cowork/
  README.md                          ← цей файл
  cyberplain-analytics-brief/        ← скіл для Cowork (папка = вміст zip)
    SKILL.md
    references/
      brief-format.md                ← формат брифу (контракт між Cowork і Claude Code)
      vulnerability.md  attack.md  report.md   ← шаблони
      style.md                       ← тон і редакційні правила
      portfolio.md  attack-v20.md  existing.md ← ЗГЕНЕРОВАНІ з репозиторію (npm run cowork:skill)
  dist/cyberplain-analytics-brief.zip ← zip для завантаження (не в git)
```

## Налаштування (один раз)

1. Зберіть zip: `npm run cowork:skill` → `cowork/dist/cyberplain-analytics-brief.zip`.
2. У Claude: **Settings → Capabilities → Skills → Upload skill** — завантажте zip. Переконайтесь, що скіл увімкнено
   (а також Code execution / File creation і вебпошук — без них скіл не прочитає довідники й не знайде джерела).
3. Створіть у Cowork проєкт, напр. «CyberPlain · Аналітика», і вставте в його інструкції текст нижче.
4. За бажання додайте в файли проєкту PDF-звіти, які збираєтесь розбирати.

### Інструкції проєкту (вставити як є)

```text
Це робочий простір аналітики для сайту CyberPlain (cyberplain.alestalab.top) — некомерційного «перекладача»
кібербезпеки на людську мову для менеджерів з продажу. Автор — Роман Розумей.

Кожна нова сесія — розбір однієї теми для розділу «Аналітика»: вразливості (CVE), атаки чи звіту. Автор зазвичай просто
кидає матеріали (посилання, PDF, текст, скриншоти) без пояснень — цього досить, щоб почати.

Завжди використовуй скіл cyberplain-analytics-brief і працюй до кінця без зупинок:
1. Сам визнач вид статті й ID за правилами скіла. Перепитуй лише тоді, коли матеріали явно про кілька різних тем.
2. Матеріали автора — відправна точка, а не межа: знайди й відкрий першоджерела (виробник, CVE/NVD, CISA KEV,
   CERT-UA/CERT-EU, звіт жертви чи дослідників) і звір кожен факт.
3. Віддай один файл <id>.md точно у форматі скіла і збережи його в підключену папку проєкту. Цей файл автор передасть
   Claude Code, який перевірить його і опублікує статтю без додаткового дослідження.
4. У відповіді — три рядки: що в статті, що в ній наше (редакційне), що лишилось відкритим.

Правила:
- Лише перевірені факти. Чого не вдалося перевірити — у «Питання до автора», не в текст. URL — лише ті, що ти відкрив.
- Техніки — лише ATT&CK Enterprise v20 зі списку скіла; рішення — лише класи з portfolio.md. Чесно познач, що назвало
  джерело, а що — наше зіставлення.
- Українська мова, дружній і поважний тон, аналогії з життя; англійську версію не пиши.
- Атаку описуй детально: для кожного кроку — що робить зловмисник, що отримує (проміжний результат), чим це загрожує,
  які сліди лишає і які класи рішень розривають крок найраніше й найнадійніше, з обґрунтуванням. Мета — щоб читач розумів
  ризик кожного кроку і міг обрати та обґрунтувати найефективніший захист.
- Не пиши інструкцію для атаки: без коду експлойтів і PoC, пейлоадів, готових команд і запитів із параметрами, рецептів
  обходу захисту. IoC не переносимо — посилання на джерело.
- Вразливість — завжди з «Ланцюжком атаки» (4–7 кроків від пошуку вразливих систем до мети), кожен крок зі статусом
  «підтверджено» (бачили в реальних атаках) чи «ймовірно».
- Звіт — з «Як отримано дані», у кожному висновку «Основа» (дані звіту / рекомендація автора / наш висновок) і «Що на кону»,
  та 3–5 «Питань до замовника».
- Ілюстрація — у кожній статті: схема, коли є механіка, послідовність чи цифри для порівняння; інакше — образна
  ілюстрація головної думки.
```

## Робочий цикл

1. У проєкті Cowork: «Розбери CVE-2026-XXXXX для CyberPlain» / «Зроби бриф атаки … за звітом CERT-UA» / «Розбери цей PDF».
2. Перевірте бриф: розділи «Питання до автора» і «Перевірка фактів», позначки `джерело` / `редакція`.
3. Надішліть файл у сесію Claude Code з репозиторієм: «Опублікуй бриф» (скіл `publish-analytics`). Claude Code перевірить
   формат скриптом (`npm run brief:check -- <файл>`), а зміст — двома рецензентами-субагентами на економній моделі (факти й подача; ATT&CK і класи
   рішень), які за потреби звіряють спірні знахідки одне одного. Що змінює зміст — питання вам; далі збірка, перевірка
   сторінок на 375 і 1440 px і коміт. «Опублікуй без рецензії» — лише перевірка формату (швидше й дешевше).

## Оновлення скіла

Довідники `portfolio.md`, `attack-v20.md`, `existing.md` застарівають, коли в репозиторії з'являються нові класи, продукти,
статті чи імпорт ATT&CK. Після таких змін: `npm run cowork:skill` і перезавантажте zip у Cowork (старий скіл видаліть або
замініть). `publish-analytics` оновлює `existing.md` сам після кожної публікації, але zip у Cowork — лише вручну;
якщо його давно не оновлювали, Cowork просто не знатиме про найновіші статті (дублікати ID все одно зловить Claude Code).

# Вендори й продукти через Claude Cowork

Та сама схема для розділу «Рішення»:

1. **Cowork — дослідження.** Скіл `cyberplain-vendor-brief`: за назвою вендора й вашими матеріалами (даташити, таблиці
   пакетів, презентації) знаходить офіційні редакції, зіставляє функції з 50 класами за правилами портфеля, пише тексти
   для продавця й віддає **MD-бриф** `vendor-<id>.md`.
2. **Claude Code — публікація.** Скіл `.claude/skills/publish-vendor`: перевірка `npm run vendor:check -- <файл>`,
   два рецензенти (редакції й тексти; класи), JSON продуктів і англійські версії, оновлення `CLAUDE.md`,
   `README.md` і довідників Cowork, перевірка сторінок, коміт.

Мапінг на ATT&CK і D3FEND іде через класи: продукт отримує техніки, ризики й покриття етапів автоматично. Тому головне в
брифі — правильні класи кожної редакції з доказами.

## Налаштування

1. `npm run cowork:skill` → `cowork/dist/cyberplain-vendor-brief.zip`; завантажте його так само, як скіл аналітики
   (Settings → Capabilities → Skills → Upload skill).
2. Створіть окремий проєкт, напр. «CyberPlain · Вендори», і вставте інструкції:

```text
Це робочий простір для розділу «Рішення» сайту CyberPlain (cyberplain.alestalab.top) — некомерційного «перекладача»
кібербезпеки на людську мову для менеджерів з продажу. Автор — Роман Розумей.

Кожна нова сесія — розбір одного вендора (або оновлення наявного). Автор пише назву вендора чи продукту і/або кидає
даташити, таблиці пакетів, презентації, прайси — цього досить, щоб почати.

Завжди використовуй скіл cyberplain-vendor-brief і працюй до кінця без зупинок:
1. Перевір, чи вендор уже є на сайті (existing-products.md): тоді це оновлення, а не новий вендор.
2. Матеріали автора — відправна точка: знайди й відкрий офіційну таблицю пакетів / редакцій і сторінки продуктів на
   сайті вендора; таблиця вендора важливіша за маркетингові описи.
3. Продукт = редакція, що продається окремо. Класи — лише з classes.md і суворо за portfolio-rules.md; для кожного класу —
   доказ із джерела. Add-on і функції, що не дотягують до класу, — у «Як класифікували», не класом.
4. Віддай один файл vendor-<id>.md точно у форматі скіла і збережи його в підключену папку проєкту. Цей файл автор
   передасть Claude Code, який перевірить і опублікує продукти без додаткового дослідження.
5. У відповіді — три рядки: скільки продуктів і лінійок, що спірне в класифікації, що лишилось відкритим.

Правила:
- Лише перевірені факти з джерел вендора. Чого не вдалося перевірити — у «Питання до автора». URL — лише ті, що ти відкрив.
- Тексти — українською, для продавця: що це, що дає замовнику, чого немає в редакції. Без маркетингу, порівнянь вендорів,
  обіцянок і цін.
- Новий клас чи зміна мапінгу класу — лише як пропозиція з доказами; рішення за автором.
```

## Робочий цикл

1. У проєкті: «Розбери вендора Sophos» / «Онови Fortinet за цим прайсом» + файли.
2. Перевірте бриф: «Питання до автора», таблиці доказів, «Рішення щодо класифікації».
3. Надішліть файл у Claude Code: «Опублікуй вендора». Після публікації перезавантажте обидва zip у Cowork — довідники
   (наявні продукти, класи, правила) змінились.
