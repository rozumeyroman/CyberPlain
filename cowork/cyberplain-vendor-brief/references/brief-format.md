# Формат брифу вендора

Один файл `vendor-<id>.md` у UTF-8: передмова (YAML між `---`), розділи з назвами **дослівно** як нижче (Claude Code
шукає їх за назвою), службові розділи. Розділ без даних — `—`, не видаляй.

## Передмова

```yaml
---
type: vendor
vendor: Fortinet              # назва вендора як на сайті (existing-products.md); однаково в усіх продуктах
id-prefix: fortinet           # початок ID усіх продуктів: латиниця малими, цифри, дефіси
mode: new                     # new — вендора немає на сайті; update — оновлення наявного
checked: 2026-11-06           # дата, коли перевіряли джерела
---
```

## Розділи для сайту

### `# <Вендор>`
Перший рядок після передмови.

### `## Джерела`
Список: `- [Назва (дата чи «жовтень 2026»)](https://…)` — таблиця пакетів першою. Матеріали автора без URL —
`- Даташит FortiGate (PDF від автора, 2026)`.

### `## Лінійки`
Огляд (для перевірки, на сайт іде через продукти):

```markdown
| Лінійка | Редакція | ID продукту | Порядок | Класи |
|---|---|---|---|---|
| FortiGate | ATP | fortinet-fortigate-atp | 1 | ngfw, sandbox, vpn |
| FortiGate | UTP | fortinet-fortigate-utp | 2 | ngfw, web-filtering, sandbox, vpn |
| — | — | fortinet-fortideceptor | — | deception |
```

### `## Продукти`
Кожен продукт — блок `### <id> · <повна назва>`:

````markdown
### fortinet-fortigate-atp · Fortinet FortiGate Advanced Threat Protection (ATP)
- Лінійка: FortiGate              # або —
- Редакція: ATP                   # або —; коротко, як у заголовку таблиці редакцій (латиницею)
- Порядок: 1                      # або —; від базової (1) до старшої
- Класи: ngfw, sandbox, vpn       # ID з classes.md; перший — головний
- URL: https://…                  # першоджерело редакції (таблиця пакетів чи сторінка продукту)

Коротко: <1–2 речення, до ~220 символів: що це і для кого. Без маркетингу.>

Що дає замовнику:
- <3–4 пункти мовою бізнесу: що зміниться в компанії; кожен ≤ ~130 символів>

Детально: <один абзац 400–1200 символів: можливості редакції людською мовою — що робить, де працює (хмара, апарат, агент),
як ліцензується словами, чим ця редакція відрізняється від сусідніх. Технічні назви функцій — у дужках.>

Чого немає:
- <чого в цій редакції немає / що докуповується: «Фільтрації вебсайтів немає — вона з пакета UTP». Немає — —>

Як класифікували:
- <1–3 пункти: що з функцій рахуємо яким класом, що лише в тексті й чому (за portfolio-rules.md)>

| Клас | Функція в джерелі | Доказ |
|---|---|---|
| ngfw | IPS, антивірус на шлюзі | Таблиця FortiGuard bundles, рядок «IPS» |
| sandbox | FortiSandbox Cloud (лише виявлення) | Там само, рядок «Sandbox» |
| vpn | IPsec/SSL VPN у FortiOS | Даташит FortiGate, розділ VPN |
````

Таблиця доказів — службова (на сайт не йде), але **обов'язкова**: рядок для кожного класу з «Класи».

### `## Рішення щодо класифікації`
Абзац (або кілька пунктів) для розділу «Портфель рішень» у `CLAUDE.md` — у тому ж стилі, що в `portfolio-rules.md`:
джерело (URL), скільки продуктів і за чим (пакети / модулі), яка функція яким класом, що лише в тексті, що не додано
й чому. І рядки для таблиці «Продукт | Класи» в тому ж форматі, що в `portfolio-rules.md`.

### `## Пропозиції змін класів`
Лише якщо потрібно: новий клас (ID, назва, що робить, ризик, які техніки й D3FEND), зміна `defenses[]` / `d3fend[]`
наявного класу — з доказом і причиною. Немає — `—`.

## Службові розділи

### `## Питання до автора`
Нумерований список: що не вдалося перевірити, де класифікація спірна, яку назву обрати. Немає — `—`.

### `## Перевірка фактів`
| Факт | Джерело | Примітка |
|---|---|---|
| ATP містить IPS і пісочницю | Таблиця FortiGuard bundles | пісочниця лише виявлення |

## Самоперевірка

- [ ] `vendor` збігається з назвою на сайті; всі ID починаються з `id-prefix` і не збігаються з наявними (крім оновлень).
- [ ] Кожен клас є в `classes.md` і має рядок у таблиці доказів; нічого з add-on не стало класом.
- [ ] Правила `portfolio-rules.md` дотримано (EPP ≠ EDR, вебфільтрація ≠ кіберрозвідка, CWPP ≠ CNAPP, VPN ≠ без VPN…).
- [ ] Лінійки: однакова `Лінійка` в редакціях, різні `Редакція`, `Порядок` від базової.
- [ ] У кожного продукту: Коротко, 3–4 «Що дає замовнику», Детально, URL; «Чого немає» там, де редакції відрізняються.
- [ ] Тексти за `style.md`, без маркетингу й обіцянок; URL лише ті, що відкривались.
