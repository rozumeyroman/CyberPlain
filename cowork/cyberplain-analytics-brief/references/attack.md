# Шаблон: атака

Приклади на сайті: `/analytics/attacks/tradertraitor-binance/`, `/analytics/attacks/datasuckers-atb/`,
`/analytics/attacks/uac-0050-dtek-litemanager/`. Сторінка: «Коротко» → «Простими словами» (схема після 2-го абзацу) →
заяви й цифри → хто атакував → ланцюжок кроків (етап ATT&CK, що відбувається, інструменти, техніки, рішення, прогалини) →
матриця «клас рішень → які кроки зупиняє» (обчислюється сама) → висновки → застереження → джерела.

**Кроки** — серце статті: 5–10 кроків у хронологічному порядку, кожен прив'язаний до одного етапу ATT&CK (ID з
`attack-v20.md`, `TA…`). Два кроки можуть мати той самий етап. Крок — це дія зловмисника, яку можна було помітити чи
зупинити, а не переказ новини. Для кожного кроку — що зловмисник робить, **що отримує** і чим це загрожує, які сліди
лишає і що його зупинить: з цього читач оцінює ризик і обґрунтовує вибір захисту. Детально, але без рецепта атаки
(`style.md` → «Деталізація атаки»).

````markdown
---
type: attack
id: <угруповання-жертва>
date: <дата атаки чи хвилі, YYYY-MM-DD>
dateNote: "<напр. 29 жовтня 2026 (крадіжка); підготовка — з червня 2026>"
actor: TraderTraitor                # як називає джерело; кілька назв — основна, решта в профілі
victim: { name: Binance, sector: криптобіржа, country: міжнародна }   # name може бути узагальненим: «державні установи»
original: null                      # якщо стаття — розбір ОДНОГО звіту: { title: "…", publisher: "…", pages: 20, url: "…" }
related-vulnerabilities: []
---
````
